# v2 performance audit — October 5, 2026

Source audit of launch/bootstrap, watchlists and collections, TMDB requests, recommendations, artwork, Discover/search, detail loading, and background animation. Fixes were applied directly. This is not a physical-device frame-rate, energy, or CloudKit benchmark.

## Findings addressed

| Area | Finding | Change |
| --- | --- | --- |
| Discover pagination | Footer was outside the lazy rows in an eager stack, creating a risk of loading pages before reaching the bottom. Failed pages had no visible retry with populated results. | Lazy footer, explicit failure/retry state, retry the failed page including a page-one refresh with retained rows. |
| Discover filter position | Genre/sort changes collapsed Browse All while loading, clamping the scroll offset. | Retain rows until replacement and reserve a viewport below the filters, including for empty/short results. |
| Discover page identity | Rankings can repeat a title across pages; total pages can exceed the accessible API range. | Deduplicate every page and appended IDs and cap pagination at 500. Reserve loading state before scheduling a page task to prevent duplicate triggers. |
| Task ownership | Discover retry/pagination and watchlist pull-to-refresh could run on canceled presentation tasks. Watchlist refresh was not retained for cancellation during a sharing transition. | View-model-owned tasks; check cancellation before applying refreshed metadata and after mapping suspensions. |
| Refresh presentation | Discover replaced successful carousels with placeholders on every refresh. A partial failure could erase a successful section. | Keep content mounted for the same type/providers/region. Clear it when filters change; preserve a section on a transient refresh failure and show an inline error above retained carousels. |
| Core Data reads | Startup-derived sections traverse title/provider relationships; collection mosaics/counts traverse entries and titles. Fetches did not prefetch these relationships. | Prefetch those known relationships on cold reads, not on every remote-change reload during CloudKit import. No model/store changes. |
| Freshness | A repeated watchlist pull could return the 10-minute response cache. | Bypass the exact metadata response URLs and HTTP response cache for an explicit pull; keep detail, season, recommendation and carousel caches. Join existing in-flight requests. Launch refresh keeps the existing six-hour gate. |
| Artwork | Shared downloads outlive canceled URL tasks; an old task could replace newer artwork or its tint. HTTP failure responses were passed to the decoder. | Cache completed artwork but reject canceled UI updates; validate HTTP success before decoding. |
| Loading-state races | An old recommendation/suggestion request could end its replacement's spinner. Person loading could return on cancellation without clearing its spinner. Season loading could publish a canceled response. | Cancellation-aware recommendation cleanup, generation-aware suggestion/person/season cleanup, and season response cancellation checks. |
| Search errors | Discover stored only the selected type's failure, so switching TV/movie segments could display the wrong outcome. An error hid retained results. | Store both errors; retain successful rows with inline errors. Omit a loading row above retained results to prevent layout shifts on each keystroke. |

## Existing strengths

- TMDB combines detail subresources into one request. Background refresh uses lean metadata responses, deduplicates collection-only titles, and limits requests to eight per batch.
- Response requests coalesce by complete URL, cache for ten minutes, and cap at 300 entries. Transient HTTP failures receive one bounded retry. Decoding runs off the main actor.
- Artwork downloads coalesce, prepare decoded images off the main actor, and use a 100 MB cost-limited memory cache. Artwork generally uses bounded TMDB sizes rather than originals.
- Search debounces 300 ms and fetches TV/movies concurrently. Its scroll container stays mounted through loading/empty/error states.
- Recommendation pools, seeds and scoring concurrency are bounded; optional scoring has a disk cache and TMDB fallback.
- Watchlists render local data before network refresh. Background mesh animation stops on disappearance and honors Reduce Motion.

## Validation

- Debug and Release unsigned Simulator builds using Xcode's installed iOS SDK.
- Reproducible source-level checks: run `./ci_scripts/check_performance.sh`. The repository harness compiles the actual Discover view model and response deduplicator, with a deterministic service double and the project's actor-isolation behavior. Checks: caller cancellation, warm-tab reuse, refresh retention/partial failure, pagination cap, duplicates within page one and across pages, failed-page rollback/retry, failed page-one refresh retry, stale-filter rejection, retained rows during genre/sort changes, media-type-specific search errors, concurrent response coalescing, scoped invalidation, exact-URL bypass preserving other cached payloads, and reuse of an in-flight download after its caller is canceled. Passed after the review fixes. No test target added. These are source-level checks, not network/UI benchmarks.
- One-off Simulator screenshot-mode smoke launch during the initial audit on iPhone 17 Pro / iOS 26.4: seed completed; Discover rendered carousels and artwork; a subsequent launch of the final Debug build rendered watchlist sections, posters and provider logos. Uses the isolated in-memory demo store.
- A one-off 10-second Time Profiler capture of idle Discover produced 901 sample rows and zero potential-hang rows at the template’s 250 ms threshold. The trace was a temporary local artifact, not evidence stored in the repository; this observation cannot be reproduced from the repository alone. Instruments reported one table without a known input source; this short Simulator capture is limited evidence and does not measure scrolling or launch.
- `git diff --check` passed. Builds retain existing actor-isolation/deprecation warnings; this audit does not constitute a Swift 6 migration.

## Remaining measurement priorities

Before launch, profile a signed Release build on the oldest supported physical device, with a large SQLite watchlist and collections: cold launch, rapid poster scrolling, repeated detail pushes, full refresh, poor connectivity, and CloudKit import. Use SwiftUI/Animation Hitches and Allocations; check SQLDebug for actual store-fault counts. Simulator smoke checks do not establish frame-time or memory budgets.

The first cold Discover carousel render still waits for the slowest parallel carousel request. The six-hour refresh stamp still considers a partially successful run complete; titles that failed may remain stale until the next refresh. Both are existing tradeoffs to revisit if slow-network/device measurements show a problem. Cold-read prefetching intentionally trades some earlier materialization for fewer store round trips; validate that tradeoff with unusually large collections. Remote-change reloads no longer request that prefetch.

Cancellation gates before applying metadata remain intentional: a sharing transition can purge the old graph, or a newer refresh can supersede the result. The shared request layer still caches downloaded data. A forced metadata refresh joins an existing request; it never invalidates unrelated completed responses.
